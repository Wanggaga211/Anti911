## 1. `ShareRpcLayout.h` —— Ring3 与 Ring0 的唯一契约

### 1.1 它为什么必须这么"干净"

```c
#ifdef KSR_KERNEL
#include <fltKernel.h>
typedef ULONG   ksr_u32;
typedef ULONG64 ksr_u64;
#else
#include <stdint.h>
typedef uint32_t ksr_u32;
typedef uint64_t ksr_u64;
#endif
```

- 这个头文件同时被用户态教学器和（将来的）驱动包含，所以里面**只能出现两边都认得的类型**：
  `u32/u64`、固定偏移、普通结构体。
- 一旦在里面写 `#include <windows.h>`、`HANDLE`、`CONTEXT` 这种"只属于某一侧"的东西，
  另一侧就编译不过（内核里没有 CRT、没有 `HANDLE` 的完整定义）。
- `KSR_KERNEL` 这个宏就是"我现在站在哪一侧"的开关。

### 1.2 64KB 段的内存地图

| 偏移 | 常量 | 放什么 |
|---|---|---|
| `0x0000` | `KSR_OFF_HEADER` | 段头 `KSR_HEADER`：魔数、版本、状态、统计 |
| `0x0200` | `KSR_OFF_STUB` | 可执行的 stub 块：代码 + 函数槽 + FXSAVE 区 + CONTEXT 副本 |
| `0x1000` | `KSR_OFF_MAILBOX` | 命令信箱 `KSR_MAILBOX`：请求/应答，零拷贝传参 |
| `0x2000` | `KSR_OFF_LOG` | 留给演示的文本日志区 |

- 为什么 stub 块放在 `0x200`：页内偏移 0 的段头需要保留，`0x200` 之后的块**仍然 16 字节对齐**，
  满足 `fxsave` 对操作数对齐的要求（`0x200 + 0x110 = 0x310`，`0x310 % 16 == 0`）。
- `KSR_STUB_MAX = 0xE00`：块上限，必须小于 `0x1000 - 0x200 = 0xE00`，
  否则 stub 会压到信箱区（代码里有运行时校验，超了就报错退出）。

### 1.3 `KSR_HEADER` 逐字段

```c
ksr_u32 Magic;       /* 必须等于 KSR_MAGIC(0x4B535252 'KSRR') */
ksr_u32 Version;     /* 必须等于 KSR_VERSION(1) */
ksr_u32 HeaderSize;  /* sizeof(KSR_HEADER) */
ksr_u32 State;       /* EMPTY/READY/BUSY/FAULT */
```

- `Magic`：判断"这段内存到底是不是我们的"。共享段名可枚举，别人也可能映射同名段，
  没有魔数校验就可能解析一堆垃圾。
- `HeaderSize`：**防止两侧结构体不一致**。你在用户态加了个字段、驱动没重新编译，
  两边对同一偏移的解释就不同，靠这个字段能在握手阶段直接发现。
- 统计字段（`HijackCount / DirectCallCount / SpinCount / RttTotalNs / RttSamples`）：
  让"结论"变成"可读的数字"，而不是"我觉得它跑通了"。

### 1.4 `KSR_MAILBOX` 与握手机制

```c
ksr_u32 Cmd;   ksr_u32 Done;   ksr_u32 Seq;   ksr_u32 Status;
ksr_u64 Arg0;  ksr_u64 Arg1;   ksr_u64 Result0; ksr_u64 Result1;
ksr_u64 Payload[32];   /* 256 字节，请求参数直接放这里，不做拷贝 */
```

握手分三步（控制器 → agent）：

1. 控制器写 `Cmd / Arg0 / Payload[]`，把 `Done` 清 0；
2. `_ReadWriteBarrier()` 之后写 `Seq = i`（**序号变化就是"有新活"的信号**）；
3. agent 看到 `Seq != lastSeq` → 干活 → 写 `Result0` → `_ReadWriteBarrier()` → `Done = 1`。

- 为什么"用序号而不是用标志位触发"：`Done` 是**完成位**，`Seq` 是**请求位**，分开之后
  "上一轮没做完就来下一轮"也能被检测出来（`lastSeq` 不匹配）。
- `Payload[32]` 就是"零拷贝"的体现：控制器写进去，agent 就在**同一个物理地址**上算校验和，
  全程没有一个 `memcpy`。

## 2. `KsrLab.h` —— 公共声明

关键内容（常量与导出符号）：

```c
#ifndef NT_SUCCESS
#define NT_SUCCESS(Status) (((NTSTATUS)(Status)) >= 0)
#endif

#define KSR_STUB_OFF_SLOT  0x100    /* 载荷函数指针 */
#define KSR_STUB_OFF_FX    0x110    /* FXSAVE 区（512B，16 对齐） */
#define KSR_STUB_OFF_CTX   0x320    /* CONTEXT 副本（0x4D0） */
#define KSR_STUB_SIZE      0x7F0    /* 块总长 = 2032 字节 */
```

- `NT_SUCCESS`：`ntdll` 的返回值是 `NTSTATUS`，`>= 0` 才算成功。
  用户态没有这个宏（那是 WDK 里的），自己补一个，免得每个判断都写 `if (st >= 0)`。
- 四个偏移必须和 `NtStub.asm` 里的 `OFF_SLOT / OFF_FX / OFF_CTX / BLOCK_END` **完全一致**。
  一致性不是靠自觉，而是靠运行时对拍（见 5.1）。

从汇编导出的符号（C 侧以 `extern` 声明，链接期由 `ml64` 生成的 `.obj` 提供）：

```c
extern char KsrHijackStub[];    /* 桩的入口 */
extern char KsrHijackStubEnd[]; /* 桩的结尾（算长度用） */
extern char KsrHijackBodySlot[];/* 载荷指针槽 */
extern char KsrHijackFxArea[];  /* FXSAVE 区 */
extern char KsrHijackCtx[];     /* CONTEXT 副本 */
```

> 用 `char[]` 而不是 `void*` 是有意的：`KsrHijackStubEnd - KsrHijackStub` 才能算出**字节长度**。
> `void*` 相减在 C 里是非法/未定义行为。

## 3. `Layer1_SharedMem.c` —— 第一层

### 3.1 `KsrShareCreate`：建段 + 映射 + 初始化段头

```c
sprintf_s(name, sizeof(name), "Local\\KShareRpcLab_%s_%lu", tag, GetCurrentProcessId());
```

- 名字里带 PID：同一个程序开两份也不会互相覆盖（调试时特别有用）。

```c
HANDLE hMap = CreateFileMappingA(INVALID_HANDLE_VALUE, NULL, PAGE_EXECUTE_READWRITE,
                                 (DWORD)((ULONGLONG)KSR_SECTION_SIZE >> 32),
                                 (DWORD)(KSR_SECTION_SIZE & 0xFFFFFFFF), name);
```

- 第一个参数 `INVALID_HANDLE_VALUE`：**不挂文件**，用分页文件支撑（pagefile-backed section）。
- 第 3、4 个参数是**高 32 位 / 低 32 位大小**。这里踩过一个编译坑：直接写
  `(DWORD)(KSR_SECTION_SIZE >> 32)` 会触发 `C4293`（对 32 位数右移 32 位是未定义行为），
  必须先转成 `ULONGLONG` 再移。
- `PAGE_EXECUTE_READWRITE`：为第三层的 stub 准备的（代价见 README 的局限一节）。

```c
void* base = MapViewOfFile(hMap, FILE_MAP_ALL_ACCESS | FILE_MAP_EXECUTE, 0, 0, 0);
```

- `FILE_MAP_EXECUTE` 必须显式加上，否则视图不可执行，第三层往里面跳会直接 AV。

```c
KSR_HEADER* hdr = (KSR_HEADER*)base;
hdr->Magic = KSR_MAGIC; hdr->Version = KSR_VERSION;
hdr->HeaderSize = (ksr_u32)sizeof(KSR_HEADER); hdr->State = KSR_STATE_READY;
```

- 段头写死之后，对面（agent 或驱动）第一件事就是校验这三个字段，
  不合格就"这不是我的段"，直接退出。

### 3.2 `AgentProc`：目标侧 agent 的雏形

```c
hdr->AgentPid = GetCurrentProcessId();
hdr->AgentTid = GetCurrentThreadId();
```

- 真实工程里，这个 agent 是"第一次 bootstrap 注入"带进目标的那段代码；
  本 demo 直接开一个线程模拟它，好处是**可以反复跑、不影响别人**。

```c
uint32_t seq = mb->Seq;
if (seq != lastSeq) { lastSeq = seq; ... }
```

- **轮询序号**而不是等事件：这是共享内存通信的典型形态（没有内核对象可等）。
  代价是空转烧 CPU，所以循环里有 `_mm_pause()`。
- 为什么不用 `Sleep(1)`：`Sleep` 会把时延从"纳秒"抬到"毫秒"，测出来的就不是内存时延了。

```c
uint64_t sum = mb->Arg0;
for (int i = 0; i < 32; i++) sum += mb->Payload[i] * (uint64_t)(i + 1);
mb->Result0 = sum;
```

- 这是**故意设计成"必须读到控制器写的那 256 字节"才能算对**的校验方式：
  任何一个字节没传到位，结果就对不上。

### 3.3 `KsrDemo1`：计时与校验

```c
for (int warm = 0; warm < 200; warm++) { ... }   /* 预热 200 次 */
```

- 预热的目的是排除**首次缺页**（第一次访问这段内存会触发缺页中断，那一次是微秒级，
  混进平均值会把数字抬高好几倍）。

```c
QueryPerformanceCounter(&t0);
mb->Seq = (uint32_t)(i + 1000);
while (mb->Done == 0) { _mm_pause(); if (++guard > 200000000) break; }
QueryPerformanceCounter(&t1);
```

- 计时点**只包住"发信号 → 收到完成"**这一小段，前面准备 `Payload` 的时间不算在内。
- `guard` 是死循环保护：万一 agent 线程被调度走了，不能让主流程卡死。

```c
uint64_t expect = mb->Arg0;
for (int k = 0; k < 32; k++) expect += (uint64_t)(i * 32 + k) * (uint64_t)(k + 1);
if (mb->Result0 != expect) bad++;
```

- 控制器**本地独立算一遍期望值**，再和 agent 算的比对。这样"两边算法都错但错得一样"也能发现
  （虽然本 demo 里两边公式是同一份，真实工程里应该走两套独立实现）。

## 4. `Layer2_DirectSyscall.c` —— 第二层

### 4.1 `KsrResolveSsn`：从机器码里读服务号

```c
uint8_t* p = (uint8_t*)GetProcAddress(ntdll, funcName);
```

- 先拿函数入口。注意这里拿的是 **ntdll 里的地址**，不是 kernel32 的（kernel32 会再转一层）。

```c
if (p[0] == 0xE9) { p = p + 5 + *(int32_t*)(p + 1); continue; }   /* jmp rel32 */
if (p[0] == 0xEB) { p = p + 2 + *(int8_t*)(p + 1);  continue; }   /* jmp rel8  */
```

- "转发桩"就是一条跳转指令。`jmp rel32` 的位移是**相对于下一条指令**的，所以是
  `当前地址 + 5（指令长度） + 位移`。
- 最多跟 8 跳：防止遇到环形转发把自己跳死。

```c
if (p[0] == 0x48 && p[1] == 0xB8) return FALSE;   /* mov rax, imm64 → 已被 hook */
```

- `48 B8` 后面跟 8 字节立即数，是"64 位绝对地址跳转"的前半段。
  正常 `Nt*` 桩不会这么写，出现就说明入口被改过，SSN 已经读不出来。

```c
if (p[0] == 0x4C && p[1] == 0x8B && p[2] == 0xD1 && p[3] == 0xB8) {
    *ssn = *(uint32_t*)(p + 4);
    return TRUE;
}
```

- 对应 `mov r10, rcx` + `mov eax, imm32`：第 4 字节开始的 4 字节就是 SSN。
- 兜底：在前 32 字节里找 `B8 imm32 0F 05`（`mov eax,imm32` + `syscall`）的组合，兼容个别形状不同的桩。

### 4.2 `HookInstall` / `HookRestore`：装/卸 inline hook

```c
memcpy(g_hookOrig, target, 12);          /* 先把原始字节存下来 */
```

- **必须先存后改**。顺序反了，恢复时就把补丁写回去了（这个错误非常常见）。

```c
patch[0]=0x48; patch[1]=0xB8; *(void**)(patch+2) = hookFn; patch[10]=0xFF; patch[11]=0xE0;
```

- 编码是 `mov rax, <64位地址>` + `jmp rax`，共 10 + 2 = 12 字节。
- 为什么不用 `jmp rel32`（只要 5 字节）：`rel32` 只能跳 ±2GB，而 EXE 和 ntdll 的地址
  在 ASLR 之后可能相距很远，跳不过去。用"绝对地址 + 间接跳"就没有距离限制。

```c
VirtualProtect(target, 16, PAGE_EXECUTE_READWRITE, &old);
memcpy(target, patch, 12);
VirtualProtect(target, 16, old, &tmp);
FlushInstructionCache(GetCurrentProcess(), target, 12);
```

- `VirtualProtect` 是必须的：代码段默认只读（`PAGE_EXECUTE_READ`），直接写会 AV。
- `FlushInstructionCache` **也是必须的**：CPU 有独立的指令缓存（I-cache），
  你改了内存里的字节，CPU 可能还在执行旧的解码结果。写完必须刷。

```c
return memcmp(g_hookTarget, g_hookOrig, 12) == 0;   /* 恢复后按字节验证 */
```

- **不验证就等于没恢复**。第三方（杀软、系统自己的热补丁）也可能在动这几字节，
  比对失败就说明"别人也插了一手"。

### 4.3 `FakeEdrHook`：hook 命中后怎么"代替"原函数

```c
InterlockedIncrement(&g_hookHit);
return (NTSTATUS)KsrNtStub(g_hookSsn, (uint64_t)(uintptr_t)proc, cls, buf, len, ret, 0);
```

- 正常 inline hook 应该"执行被偷走的指令 → 跳回原函数 +N"（这叫 trampoline）。
  这里**故意不做**，原因就是实测出来的那条：桩不是 12 字节整齐结构（见 4.4）。
- 直接用自己的 syscall 桩补一次同 SSN 的调用，**语义完全等价**（同一个内核服务、同样的参数）。
  代价是"如果有 hook 链，这条链断了"——但这是演示，不是生产。

### 4.4 `KsrDemo2`：四条可验证结论怎么来的

```c
LONG c0 = g_hookHit;
stA = ((PFN_NtQueryInformationProcess)pQip)(GetCurrentProcess(), 0, &a, sizeof(a), NULL);
LONG c1 = g_hookHit;
if (c1 - c0 != 1) bad++;        /* 走 ntdll 必须命中 1 次 */
```

- 用**命中计数差**而不是"我觉得它进了 hook"，这是可验证性的关键。

```c
NTSTATUS stB = KsrNtStub(ssn, ..., &b, sizeof(b), 0, 0);
LONG c2 = g_hookHit;
if (c2 - c1 != 0) bad++;        /* 直连必须一次都不命中 */
```

```c
if (stA == stB && memcmp(&a, &b, sizeof(a)) == 0)   /* 两路返回必须完全一致 */
```

- 比对的是**整个 `KS_PBI`（进程基本信息）结构**，不是只比 `Status`。
  只有内容和状态都一样，才能说"落的是同一个内核服务"。

```c
BOOL ok2 = KsrResolveSsn("NtQueryInformationProcess", &ssn2);   /* hook 之后再解析 */
```

- 这一步是**故意让它失败**的教学点：它证明"hook 抹掉了 `mov eax, imm32`"，
  所以真实载荷必须"先取号、后干活"。

### 4.5 那个 `__try / __except`

```c
__try { stA = ((PFN...)pQip)(...); }
__except (RecordFilter(GetExceptionCode(), GetExceptionInformation())) { ... }
```

- 平时可以删掉，但**调试期非常有用**：`RecordFilter` 会把异常码、**指令地址**、
  访存类型（读/写/执行）、**访存地址**都存下来。
- 我第一次跑的时候就是靠它拿到"崩在 `trampoline+8`，访存地址 `0xFFFFFFFFFCB84808`"，
  才反推出"12 字节硬切把一条 `test` 指令剪断了"。
- 注意 `GetExceptionInformation()` **只能在 `__except` 的过滤表达式里调用**，
  所以必须包一层函数 `RecordFilter(DWORD, PEXCEPTION_POINTERS)`。

### 4.6 参数搬运：`KsrNtStub` 的七个参数怎么对齐

```c
KsrNtStub(ssn, (uint64_t)(uintptr_t)GetCurrentProcess(), ..., 7 个参数)
```

- C 侧声明是 7 个参数（SSN + 最多 6 个系统调用参数）。汇编侧按"第 4 个参数起在栈上"
  去取（`[rsp+28h] / [rsp+30h] / [rsp+38h]`），这个偏移是 **x64 ABI 固定**的：
  返回地址 8 字节 + 影子空间 32 字节 = `0x28`，之后每 8 字节一个参数。

## 5. `NtStub.asm` —— 两条桩

### 5.1 为什么要有"运行时对拍"

C 侧常量 `KSR_STUB_OFF_SLOT=0x100` 和汇编里的 `OFF_SLOT EQU 100h` 是**两份独立的数字**，
任何一边改了另一边没改，整块搬迁的 stub 就会把函数指针写错地方。所以 `KsrDemo3` 里：

```c
if ((size_t)(KsrHijackBodySlot - KsrHijackStub) != KSR_STUB_OFF_SLOT || ... )
{
    KsrLog("[L3] stub 块布局与 C 侧常量不一致 ...");
    return 0;              /* 直接拒绝运行，而不是带着错跑 */
}
```

- 这比"注释里写一句请保持一致"可靠一万倍：**用导出的符号反算真实偏移，再和常量比**。

### 5.2 `KsrNtStub`（直连桩）逐条

```asm
mov     r10, rdx                 ; a1: rdx -> r10
mov     rdx, r8                  ; a2: r8  -> rdx
mov     r8,  r9                  ; a3: r9  -> r8
mov     r9,  qword ptr [rsp+28h] ; a4: 栈 -> r9
mov     rax, qword ptr [rsp+30h] ; 读 a5
mov     qword ptr [rsp+28h], rax ; a5 写到第 5 个参数槽
mov     rax, qword ptr [rsp+38h] ; 读 a6
mov     qword ptr [rsp+30h], rax ; a6 写到第 6 个参数槽
mov     eax, ecx                 ; SSN 放进 eax
syscall
ret
```

- 逐条读法：**先把参数搬成内核要的顺序，最后才放 SSN**。
  `eax` 最后写，是因为前面搬参数要用 `rax` 当临时寄存器。
- 为什么要 `rax` 做二传：`mov [rsp+28h], [rsp+30h]` 这种"内存到内存"的指令 x86 不存在，
  必须经过一个寄存器。用 `rax` 而不是 `r10`，是因为 `r10` 已经装好 a1 了。
- `syscall` 的返回值在 `eax`（`NTSTATUS`），直接 `ret` 就交给 C 侧了。

### 5.3 `KsrHijackStub`（劫持桩）逐条

```asm
ORG 0
KsrHijackStub LABEL BYTE
    lea     r14, KsrHijackStub
```

- `lea r14, KsrHijackStub` 会被汇编成 `4C 8D 35 F9 FF FF FF`（实测抓到的就是这 7 字节）：
  `lea r14, [rip - 7]`。**这条是 RIP 相对的**，整块搬到任何地址，`r14` 都会等于"块自己的首地址"。
- `ORG 0`：告诉汇编器"从段偏移 0 开始算"，后面 `LABEL` 的偏移才是从 0 起的。

```asm
    fxsave  [r14+OFF_FX]
```

- 保存 512 字节浮点/SSE 状态。`fxsave` 要求目标地址 **16 字节对齐**（`0x110` 满足）。

```asm
    and     rsp, -16
    sub     rsp, 20h
```

- `and rsp,-16`：把栈指针对齐到 16 的倍数（`-16` 就是 `0xFFFFFFFFFFFFFFF0`）。
- `sub rsp,0x20`：留 32 字节影子空间。**这两步是 x64 调用约定的硬要求**，
  少一步，被调函数里的 `movaps [rsp+..]` 就会因为地址未对齐而崩。

```asm
    lea     rcx, [r14+OFF_CTX]
    call    qword ptr [r14+OFF_SLOT]
```

- 第一个参数（`rcx`）= `CONTEXT` 副本地址；被调函数地址从槽里读，**不是硬编码**，
  这样同一段机器码可以在不同进程里放不同的载荷。

```asm
    fxrstor [r14+OFF_FX]
```

- **这一句就是"r11 惨案"的发生地**。第一版基址存在 `r11`，payload 返回后 `r11` 已是垃圾，
  `fxrstor` 直接 AV（实测崩在 `block+0x25`，正好是这条指令）。

```asm
    mov     eax, dword ptr [r14+OFF_CTX+C_EFLAGS]
    push    rax
    popfq
```

- `popfq` 一次恢复算术标志位。用 `push/pop` 而不是 `mov eflags`（后者不存在这种指令形式）。

```asm
    mov     rsp, qword ptr [r14+OFF_CTX+C_RSP]
    push    qword ptr [r14+OFF_CTX+C_RIP]
    mov     r11, qword ptr [r14+OFF_CTX+C_R11]
    mov     r14, qword ptr [r14+OFF_CTX+C_R14]
    ret
```

- 顺序要点：`rsp` 还原之后，**仍然用 `r14` 做基址**去读 `RIP`（因为 `r14` 还没还原）。
  `push` 之后 `rsp = 原RSP - 8`，`ret` 弹回正好回到原值。
- `r14` 必须**最后一个**还原——它是基址，先还就再也读不到后面的字段了。
- `r11` 在 `r14` 之前还原因顺序无关，但**不能早于**所有"用 r14 读"的指令（本实现里它不影响）。

### 5.4 块布局

```asm
ORG OFF_SLOT        ; 0x100
KsrHijackBodySlot LABEL QWORD
    DQ 0
ORG OFF_FX          ; 0x110
KsrHijackFxArea LABEL BYTE
    DB 512 DUP (0)
ORG OFF_CTX         ; 0x320
KsrHijackCtx LABEL BYTE
    DB 4D0h DUP (0)
ORG BLOCK_END       ; 0x7F0
KsrHijackStubEnd LABEL BYTE
```

- `ORG` 在这里的作用是"把当前偏移设置到指定值"，中间的空隙由汇编器/链接器保留。
  实测块长 `KsrHijackStubEnd - KsrHijackStub = 0x7F0 = 2032`，和 C 侧常量一致。

## 6. `Layer3_ChainHijack.c` —— 第三层

### 6.1 编译期断言：`CONTEXT` 偏移

```c
typedef char ksr_assert_ctx_rax [(offsetof(CONTEXT, Rax) == 0x78) ? 1 : -1];
typedef char ksr_assert_ctx_rsp [(offsetof(CONTEXT, Rsp) == 0x98) ? 1 : -1];
typedef char ksr_assert_ctx_rip [(offsetof(CONTEXT, Rip) == 0xF8) ? 1 : -1];
typedef char ksr_assert_ctx_efl [(offsetof(CONTEXT, EFlags) == 0x44) ? 1 : -1];
typedef char ksr_assert_ctx_r11 [(offsetof(CONTEXT, R11)   == 0xD0) ? 1 : -1];
typedef char ksr_assert_ctx_r14 [(offsetof(CONTEXT, R14)   == 0xE8) ? 1 : -1];
```

- 技巧：用一个"长度为 1 或 -1 的数组"当断言。条件不成立时数组长度是 -1，**编译直接失败**。
- 为什么需要：汇编里的 `C_RAX/C_RSP/... EQU 078h/098h/...` 是手写数字，
  和 `winnt.h` 里的真实布局必须一致。这组断言保证"不一致时编译不过"，
  而不是"运行时崩在别人进程里"。

### 6.2 `HijackBody`：payload

```c
InterlockedIncrement(&g_bodyRuns);
```

- 第一句就自增，控制器靠它知道"载荷开始跑了"。`Interlocked` 是因为这条线程和控制器
  是**真并发**，普通 `++` 会被编译器优化成读-改-写，丢更新。

```c
if (KsrResolveSsn("NtQueryInformationThread", &ssn)) {
    NTSTATUS st = (NTSTATUS)KsrNtStub(ssn, (uint64_t)(uintptr_t)(-2), 0, &tbi, sizeof(tbi), 0, 0);
```

- `(HANDLE)-2` 是"当前线程"的伪句柄，`NtQueryInformationThread` 认这个值。
- **这里刻意混用第二层**：证明三层能叠在一起（第三层负责"跑起来"，第二层负责"怎么调"）。

```c
    if (ctx) hdr->Reserved1[0] = (ksr_u64)ctx->Rip;
```

- 把"停在哪条指令"记进段头，方便和 worker 自己的代码段对照。

```c
InterlockedIncrement(&g_bodyDone);
```

- 最后一句自增：控制器靠**"跑完"的信号**（不是"开始跑"）来决定下一轮，
  否则下一轮可能在 stub 收尾时把它挂起（见 6.4 的坑）。

### 6.3 `WorkerProc`：纯用户态自旋

```c
while (g_hijackStop == 0) { InterlockedIncrement64(&g_spinCount); _mm_pause(); }
```

- **没有 syscall、没有锁、没有堆操作**——这就是它适合当停点的原因（见 01 文档 3.2）。
- `InterlockedIncrement64` 让 `g_spinCount` 一直变，控制器用它证明"劫持之后线程还在正常跑"。

### 6.4 `WaitForSpinStop`：挑停点

```c
for (int attempt = 0; attempt < 500; attempt++) {
    if (SuspendThread(hWorker) == (DWORD)-1) return 0;
    probe->ContextFlags = CONTEXT_FULL;
    if (!GetThreadContext(hWorker, probe)) { ResumeThread(hWorker); return 0; }
```

- **先挂起，再读**。`SuspendThread` 返回的是"之前的挂起计数"，不是布尔值，
  所以判断用 `== (DWORD)-1`（失败）。
- 读进 `probe`（**局部缓冲**），不读进共享块——这是踩过坑之后的写法。

```c
    if (GetModuleHandleExA(GET_MODULE_HANDLE_EX_FLAG_FROM_ADDRESS |
                           GET_MODULE_HANDLE_EX_FLAG_UNCHANGED_REFCOUNT,
                           (LPCSTR)(uintptr_t)probe->Rip, &hMod) && hMod == hSelf)
        return 1;
    ResumeThread(hWorker);
    Sleep(1);
```

- `FROM_ADDRESS`：把"一个代码地址"当输入，反查它属于哪个模块。
- `UNCHANGED_REFCOUNT`：只查询、不增加模块引用计数（否则每查一次就多一个引用，卸载不掉）。
- 停点不在自己模块内（比如在 ntdll、在内核）→ 放行、1ms 后重试，最多 500 次。

### 6.5 `HijackOnce`：一次完整劫持

```c
CONTEXT probe;
if (!WaitForSpinStop(hWorker, &probe)) { ... return 0; }
DWORD64 origRip = probe.Rip;
DWORD64 origRsp = probe.Rsp;
memcpy(ctxShared, &probe, sizeof(CONTEXT));
```

- 三个动作的顺序有讲究：**先确认合法 → 再记原始值 → 最后落进共享块**。
  共享块里的这份 `CONTEXT` 马上会被 stub 当成"还原源"，所以必须写"真实的原始现场"。

```c
ctxShared->Rip = (DWORD64)(uintptr_t)block;
ctxShared->ContextFlags = CONTEXT_FULL;
if (!SetThreadContext(hWorker, ctxShared)) { ResumeThread(hWorker); return 0; }
ctxShared->Rip = origRip;
```

- `ContextFlags = CONTEXT_FULL`：告诉内核"这份结构里哪些字段有效"（控制 + 整数 + 浮点）。
  不设或设错，`SetThreadContext` 会失败或只改一部分。
- **改回 `Rip` 的时机**：`SetThreadContext` 已经把"入口 = stub"交给内核了，
  此刻把内存副本改回原值，stub 收尾时读到的是"原始 RIP"，才能跳回去。

```c
LONG before = g_bodyDone;
ResumeThread(hWorker);
while (g_bodyDone == before) { _mm_pause(); if (GetTickCount() - t0 > 200) { ... } }
```

- 等的是"payload 跑完"（`g_bodyDone`），不是"开始跑"（`g_bodyRuns`）。
- 200ms 超时保护：万一停点选错、payload 没跑起来，不能让主流程卡死。

### 6.6 `KsrDemo3`：装块、起线程、三轮、验证、收尾

```c
char* block = (char*)base + KSR_OFF_STUB;
size_t stubSize = (size_t)(KsrHijackStubEnd - KsrHijackStub);
if (stubSize > KSR_STUB_MAX || KSR_OFF_STUB + stubSize > KSR_OFF_MAILBOX) { ... }
```

- 先算长度再检查边界：块不能压到信箱区。

```c
memcpy(block, KsrHijackStub, stubSize);
*(void**)(block + slotOff) = (void*)HijackBody;
```

- 整块搬运 + 只填一个槽（载荷地址）。其余全靠 RIP 相对寻址，所以**搬到别的进程也能跑**。

```c
LONG64 s0 = g_spinCount; Sleep(50); LONG64 s1 = g_spinCount;
KsrLog("[L3] 劫持后 50ms 内该线程又自旋了 %lld 次 —— 原调用链完好", (long long)(s1 - s0));
```

- 这是"线程没被弄坏"的**行为证据**：如果寄存器/栈还原错了，它压根跑不回这个循环。
  （这里踩过一个 `printf` 格式的坑：写成 `%lllld` 会被 ucrt 判为非法格式，
  触发 invalid parameter → `__fastfail` → 进程以 `0xC0000409` 退出。）

```c
if (g_bodyTid != (LONG64)workerTid) { ... ok = 0; }   /* 载荷必须跑在老线程上 */
```

- 这条是第三层最硬的证据：**TID 相同 ⇒ 没有新执行体**。

```c
g_hijackStop = 1;
WaitForSingleObject(hWorker, 2000);   /* 等线程真的退出，再拆段 */
CloseHandle(hWorker);
KsrShareDestroy(hMap, base);
```

- **顺序不能反**：线程可能还在 stub 里跑，先拆段（`UnmapViewOfFile`）会让它执行到已释放的页 → AV。
  先让线程停、等它退出，再拆。

## 7. 构建脚本

### 7.1 `ShareRpcLab\build.bat`

```
call vcvars64.bat                  ← 引入 cl/ml64/link 和 Windows SDK 路径
cl /c /utf-8 /wd4819 /O2 /W3 ...   ← 逐文件编译成 .obj
ml64 /c /FoNtStub.obj NtStub.asm   ← 汇编（MASM64）
link ... kernel32.lib              ← 链接；kernel32.lib 提供 GetProcAddress 等
```

- `/utf-8`：源码和执行字符集都用 UTF-8（否则中文串在 GBK 环境下会乱码）。
- `/wd4819`：屏蔽 MSVC 对全角标点的误报（隔离实验见 README 第 2 节）。
- `kernel32.lib` 是必须的：`CreateFileMapping`、`MapViewOfFile`、`VirtualProtect` 都在里面。

### 7.2 `Kernel\build_kernel.bat`

```
cl /c /kernel /GS- /D_AMD64_ /I<km 头> /I<km\crt> /I<shared> KShareRpc.c
link /DRIVER /SUBSYSTEM:NATIVE /ENTRY:DriverEntry KShareRpc.obj ntoskrnl.lib hal.lib
```

- `/kernel`：按内核模式编译（关掉用户态的异常处理假设等）。
- `/GS-`：内核里不用用户态的栈 cookie 机制（WDK 工程默认也是关的）。
- `/D_AMD64_`：不定义这个宏，`ntdef.h` 会直接 `#error "No Target Architecture"`（实测踩过）。
- `/SUBSYSTEM:NATIVE`：驱动是"原生子系统"镜像，不是控制台程序。
- `/ENTRY:DriverEntry`：入口点显式指定（链接器默认不认识 `DriverEntry`）。
- 产物用 `dumpbin /headers` 验过：`machine (x64)`、`subsystem (Native)`。
